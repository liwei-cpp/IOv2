Detailed Description

Abstract base carrying the polymorphic try_flush() interface.

Provides a pure virtual try_flush() so that any tie target can be flushed type-erased through a base pointer; for output streams the implementation is given by the CRTP-derived out_tie_target<T>.

Warning
Users must not derive from this class. It exists to be implemented by out_tie_target<T> alone (that is all its constructors are protected for), and a tie target should be one of this library's output streams; deriving from it serves no reasonable use. Each of its two virtuals also carries a constraint the caller cannot see: try_flush() is called while the initiating stream holds its own lock, and tied_to() while the process-wide tie_graph_mutex() is held. A custom implementation that takes a lock blockingly or calls tie() in either deadlocks, or locks a non-recursive mutex twice (undefined behavior).

virtual tie_target * IOv2::tie_target::tied_to ( ) const
inlinenodiscardvirtualnoexcept

This node's outgoing edge in the tie graph: the target this stream is tied to, or nullptr for a node that carries none.

basic_stream_common_operators::check_tie walks the chain through it to detect cycles, and out_tie_target::try_flush() to flush link by link. The edge comes through a virtual rather than a cross-cast: the ordinary and the standard streams have two different instantiations of basic_stream_common_operators as their common base, so a dynamic_cast to one of them would end the chain at a stream of the other kind – a cycle through it would go unnoticed, and a flush would not get past it. check_tie calls it while holding the process-wide tie_graph_mutex(), try_flush() without it; out_tie_target's implementation is only an atomic load, hence noexcept. The default returns nullptr, a node with no outgoing edge.

Reimplemented in IOv2::out_tie_target< T >, IOv2::out_tie_target< iostream< TDevice, TChar > >, IOv2::out_tie_target< ostream< TDevice, TChar > >, and IOv2::out_tie_target< stdout_api< TDevice, TChar > >.

virtual void IOv2::tie_target::try_flush ( )
pure virtualnoexcept

Pure virtual interface that flushes this stream and the tie chain downstream of it on a best-effort basis; implemented by out_tie_target<T>.

Warning
An implementation must never block. The sentry calls this while holding its own stream's lock, and that lock edge is invisible to the user, who therefore cannot fold it into a lock order of their own; an implementation that takes a blocking lock() brings the AB-BA deadlock straight back. On failure to acquire the lock it must return at once, without waiting and without leaving anything pending – which is why a tie is best-effort rather than a guarantee. This covers the stream lock only: once it is taken, a standard stream's flush (fflush) may still wait for stdio's FILE lock; that edge follows "stream lock first, `FILE` lock second", see the second @warning on IOv2::sync.
An implementation must swallow every exception raised by the flush, hence the noexcept. This is called from a sentry constructor, and the sentry is itself constructed inside the initiating stream's try block (see the insertion operators in ostream_operators.h). An escaping exception would be caught there and handed to the initiator's handle_exception, recording this stream's (the tie target's) failure against the initiator: it would receive a cvt_error describing someone else's iochannel and, dispatched on exception type, have a cvtfailbit set that its own pipeline never earned. The noexcept turns "a failure is recorded only on the tie target" into a compile-time constraint instead of a convention every call site must remember to honor.

Implemented in IOv2::out_tie_target< T >, IOv2::out_tie_target< iostream< TDevice, TChar > >, IOv2::out_tie_target< ostream< TDevice, TChar > >, and IOv2::out_tie_target< stdout_api< TDevice, TChar > >.
