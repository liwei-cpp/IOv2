Detailed Description

POSIX backend of the numeric facet: localeconv() and nl_langinfo(YESSTR/NOSTR), read under the thread locale a clocale_user switched to. glibc has no localeconv_l, so the _l forms are not used.

The boolean names come from YESSTR/NOSTR, an extension of IOv2's own: libstdc++, libc++ and the MSVC STL all keep "true"/"false". glibc stores one word per locale ("ja"/"nein" in de_DE), possibly an empty one (C, gv_GB). macOS stores the colon-separated list CLDR specifies – "strings that would normally be recognized as yes and no responses", led by the lower-case native word, such as de_DE's "ja:j:JA:J:yes:y:YES:Y" – and this backend takes the first item alone: it is the only one fit for output, and matching input against the whole list would clash with prefix matching ("n", "nein" and "no" sit in the same negative list). macOS's nl_langinfo falls back to the C locale's value for an empty string, so a locale there without the data gets "yes"/"no" rather than nothing.
