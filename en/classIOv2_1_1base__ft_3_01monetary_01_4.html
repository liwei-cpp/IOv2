Detailed Description

Base class for the monetary facet, providing POSIX lconv-to-pattern conversion utilities.

This class defines the part enum representing the components of a monetary format, the pattern type describing a complete format ordering, and protected static helpers that convert POSIX *_cs_precedes, *_sep_by_space, and *_sign_posn flags into a pattern. The monetary_conf specializations inherit from this class.

Note
This class is not instantiated directly; it serves only as the base for monetary_conf.

◆ s_construct_pattern()

pattern IOv2::base_ft< monetary >::s_construct_pattern ( pattern_spec spec)
inlinestaticprotected

Builds a monetary format pattern from POSIX lconv flags.

Combines the three flags in pattern_spec (symbol position, space, sign-string position) into a four-element pattern that satisfies moneypunct constraints. Key invariants:

  • Two things are laid out: the amount and the currency symbol. For sign_posn 3 and 4 the sign string is glued to the symbol's front or back and travels with it; for the other values it brackets the whole field instead (in front for 0 and 1, behind for 2).
  • If precedes, the symbol (with any sign glued to it) comes before value; otherwise reversed.
  • With sep_by_space 1, the space sits on the seam between the symbol (with any sign glued to it) and the amount.
  • With sep_by_space 2, the space sits next to the sign string: between it and the symbol when the two are glued together, otherwise between it and the amount (C11 7.11.2.1 EXAMPLE 2). With sign_posn 0 the sign is the pair of parentheses around the whole field, and no space is added.
  • Either way the space is neither the opening nor the closing element.
  • Without a space the field is one slot short; none fills the tail, which is the only position it is allowed to hold.
  • A sign_posn outside 0–4 or a sep_by_space outside 0–2 falls back to s_default_pattern.
Parameters
specA spec struct containing precedes, sep_by_space, and sign_posn.
Returns
The constructed four-element pattern.

inlinestaticprotected

Takes the currency code out of lconv::int_curr_symbol, dropping the fourth character C defines.

C11 7.11.2.1 makes the first three characters of int_curr_symbol the ISO 4217 code and the fourth the separator between the international symbol and the amount, and says "For int_p_sep_by_space and int_n_sep_by_space, the fourth character of int_curr_symbol is used instead of a space": whether and where to separate is int_*_sep_by_space's to say, not something the symbol carries. So the symbol kept is the code alone, and the pattern's space does any separating. The fourth character itself is not kept: in all known data it is a space (every glibc and macOS locale), and the Windows UCRT gives three characters only. The wide configurations call this after converting, so it counts characters.

Parameters
sint_curr_symbol, already in the configuration's character type.
Returns
The string less its last character if it is four long, else as it is.

◆ s_monetary_unavailable()

bool IOv2::base_ft< monetary >::s_monetary_unavailable ( const detail::monetary_raw_punct & raw)
inlinestaticprotected

Tests whether lconv provides no monetary data at all.

ISO C specifies CHAR_MAX for char members and "" for char* members to mean the value is "not available in the current locale", and mandates these sentinels for every monetary member in the "C" locale (the comments on the §7.11 struct lconv declaration are normative). POSIX likewise states "All values shall be unavailable" for LC_MONETARY in the POSIX locale.

The standard defines availability only per member — there is no locale-level "no monetary data" predicate, and partial availability is permitted. So this function conjoins every field this class would substitute rather than inferring the whole from any single one.

Parameters
rawThe lconv data the platform backend copied out.
Returns
true if the signs, currency symbols and fractional digits are all unavailable.

◆ s_norm_flag()

int8_t IOv2::base_ft< monetary >::s_norm_flag ( char v)
inlinestaticprotected

Normalizes a POSIX lconv boolean-flag field by eliminating the CHAR_MAX sentinel.

POSIX fills lconv's *_cs_precedes / *_sep_by_space with CHAR_MAX when the field is "not available" in the locale. s_construct_pattern interprets these flags as booleans, where a raw CHAR_MAX would wrongly read as truthy (i.e. "symbol precedes" / "space present"); this function maps the sentinel to 0 — the conservative default — mirroring the frac_digits handling. The test must happen before any narrowing, so callers pass the raw char lconv field here rather than the narrowed argument. (*_sign_posn needs no such helper: it has a range of its own, and CHAR_MAX falls outside 0–4, so s_construct_pattern's range check already funnels it to s_default_pattern.)

Parameters
vThe raw char lconv flag field.
Returns
The normalized value: 0 if v == CHAR_MAX, otherwise static_cast<int8_t>(v).
