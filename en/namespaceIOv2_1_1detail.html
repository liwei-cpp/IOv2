template<typename TValue>
using IOv2::detail::in_target_t
Initial value:
std::conditional_t<std::is_lvalue_reference_v<TValue>,
std::remove_reference_t<TValue>,
const std::remove_cvref_t<TValue>>

The type actually written back to on extraction: an lvalue target keeps its type, an rvalue target is demoted to const.

Note
This layer is what decides "can this be written into". It is what rejects is >> 5 and is >> const_obj: the sread for int takes an int&, which a const int& cannot match. A manipulator produced by a factory such as setw(5) is a prvalue, but its sread does not modify the manipulator object and takes a const reference, so it passes.

◆ ctype_byte_is_char()

bool IOv2::detail::ctype_byte_is_char ( int ,
clocale_handle  )
constexprnoexcept

Whether byte c is a character of its own in loc, fit for is*_l/to*_l.

Always true on glibc, which does not classify high bytes of a multibyte locale in the first place. macOS classifies a byte as the Unicode code point of the same value, whatever the encoding: under UTF-8 it makes 0x80-0x9F cntrl and 0xE9 a letter, although there they are only parts of multibyte sequences. So on macOS a high byte of a multibyte locale belongs to no class and keeps its case, as on glibc.

◆ ctype_iswctype()

bool IOv2::detail::ctype_iswctype ( wint_t c,
ctype_wclass cls,
clocale_handle  )
inlinenoexcept

Whether c belongs to cls, a mask from ctype_wctype (c belongs if it has any of its bits). The bits of c come from GetStringTypeW(CT_CTYPE1, ...); the file comment says why.

print is decided apart: wctype("print") is _BLANK|_PUNCT|_ALPHA|_DIGIT, and GetStringTypeW gives tab C1_BLANK as well. C makes printing and control characters disjoint (C11 7.4/3), so a blank prints only if it is not a control character, as in the byte-wise ctype_isprint.

◆ ctype_map_case()

wint_t IOv2::detail::ctype_map_case ( wint_t c,
unsigned long flags,
clocale_handle loc )
inlinenoexcept

Case-maps one UTF-16 code unit by loc's LC_CTYPE; flags is LCMAP_UPPERCASE or LCMAP_LOWERCASE.

Not the UCRT's _towupper_l/_towlower_l: below 256 they look the character up in a table built from the locale's code-page bytes, using the code point as a code-page byte, which is wrong under a code-page locale (measured by the probe: U+00FF -> U+009F under 1252, U+00FF -> U+00DF under 1251, U+00DF -> U+00BA under 1253). LCMapStringEx maps by Unicode and is right in every locale; LCMAP_LINGUISTIC_CASING makes it agree with glibc (U+00B5 -> U+039C, U+0131 -> I, U+01C5 -> U+01C4, Turkish i -> U+0130).

The "C" locale has no BCP-47 name and, like the UCRT's and glibc's "C", maps ASCII only. Returns c if the mapping fails or does not give a single code unit.

◆ messages_language_candidates()

std::vector< std::string > IOv2::detail::messages_language_candidates ( const std::vector< std::string > & names)
inline

Turns the language names a system gives (BCP-47) into candidate .mo directory names, in order of preference.

Each name becomes ll_CC and ll (just ll without a region), and the whole list is deduplicated: {"zh-CN", "en-US"} gives zh_CN, zh, en_US, en. The language is the first subtag (lower-cased); the region is a subtag of two letters (upper-cased) or three digits; script subtags (Hans, Latn) and variants are dropped; extensions and private use, which start at a single-character subtag, are not read. So zh-Hans-CN gives zh_CN, zh, and es-419 gives es_419, es. A name whose first subtag is not 2 to 8 letters is skipped. Both - and _ separate subtags.

The user does not write the system's list the way they write LANGUAGE, so the fallback without the region is added here. A known shortfall: sr-Latn-RS gives sr_RS, sr, where gettext's convention names Latin-script Serbian sr@latin.

◆ timeio_era_from_raw()

template<typename TEntry, typename TConv>
TEntry IOv2::detail::timeio_era_from_raw ( const timeio_raw_era & raw,
TConv conv )

Turns one era the backend gave into an era_entry: the name and the format through conv, the dates as they are, the direction normalized.

direction is normalised to exactly +1 / -1 so that the linear formula

era_year = offset + (calendar_year - from_year) * direction
IOv2::tz_level::offset
@ offset
Parses the UTC offset from z; Z is still matched literally.
Definition timeio.h:743

is uniformly valid for all era types. The normalisation mirrors glibc's era.c (≈ line 98, https://github.com/lattera/glibc/blob/master/time/era.c): for forward eras (from ≤ to, e.g. AD / Japanese / Thai), the marker maps directly: '+' → +1, '-' → -1; for backward eras (from > to), the marker is intentionally inverted. The reason: in a backward era, from_year is the epoch and to_year is a sentinel for "negative infinity". As the calendar year moves away from the epoch toward the past, (calendar - from_year) grows increasingly negative; the normalised negative direction turns that distance into a positive era year, so the same formula works in either chronological direction.

The backward branch is reached by real locales, not just in theory: ja_JP's 紀元前 and the 民前 of zh_TW / cmn_TW / hak_TW / lzh_TW / nan_TW are all backward eras. Measured against this machine's glibc data, 18 of the 108 records across the 24 locales that carry era data are backward.

◆ timeio_normalize_format()

template<typename CharT>
std::optional< std::basic_string< CharT > > IOv2::detail::timeio_normalize_format ( std::basic_string_view< CharT > fmt)

Normalizes a locale-supplied time format string into the form this library's timeio understands.

A format string from the C library (nl_langinfo() on POSIX) is locale data, not something the user wrote, and it may use glibc's extended syntax, whereas timeio implements only the standard grammar (%, an optional E or O modifier, a specifier). Left as-is, timeio's put side echoes an unrecognized sequence literally together with its % (matching strftime for genuinely unknown specifiers), so a user who wrote just c or x gets output containing a %, which the get side may then read back as silently wrong values. This function converts once, where locale data enters the library:

  • Padding flags (- _ 0 ^ #) and field widths are dropped: they affect only padding and case, so field order, separators and language all survive;
  • glibc extensions that have an equivalent standard specifier are rewritten: l to I, k to H, P to p;
  • E / O modifiers are preserved;
  • A trailing lone % with no specifier after it is kept verbatim, preserving the behaviour pinned by entry 329.

If the specifier is still outside the supported set after that, the result is std::nullopt and the caller falls back for the whole string: losing the locale's field order is preferable to emitting text this library cannot read back. Only an ASCII character can be a specifier.

Note
This applies only to locale-supplied format strings. A format string the user passes to put_time / get_time does not go through here, and its unknown specifiers are still echoed per the existing contract.
Template Parameters
CharTThe character type of the format, shared by the narrow and the wide configurations.
Parameters
fmtThe locale-supplied format string.
Returns
The normalized format string, or std::nullopt if it holds a specifier with no equivalent, in which case the caller substitutes a whole-string fallback.

◆ timeio_read_eras()

std::vector< timeio_raw_era > IOv2::detail::timeio_read_eras ( )
inline

The eras of the calling thread's locale: glibc's era binary table, parsed; nothing on the other POSIX systems (macOS).

Precondition
The caller has made the target locale current on the calling thread (through a clocale_user or the like). nl_langinfo() reads that locale; the pointers it returns stay valid until the next nl_langinfo() call, and this function is done with them before then.
Note
glibc's input layout (trusted, not validated) This is the single place where the glibc era binary layout is trusted. nl_langinfo(_NL_TIME_ERA_ENTRIES) is assumed to point at exactly _NL_TIME_ERA_NUM_ENTRIES consecutive, well-formed records; the pointer walk is unchecked, so malformed or truncated locale data (a tampered locale database, say) can cause out-of-bounds reads. System locale data is treated as trusted; if era data could ever come from an untrusted source, this is the boundary to harden.

Each record, relative to its start, is laid out as:

  • an 8 × int32 header (read via memcpy): [0] direction marker ('+' / '-') [1] offset [2] from_year - 1900 [3] from_month - 1 [4] from_day [5] to_year - 1900 [6] to_month - 1 [7] to_day
  • a NUL-terminated narrow name, then a NUL-terminated narrow format string
  • padding to the next 4-byte boundary (relative to the record's start)
  • a NUL-terminated wide name, then a NUL-terminated wide format string
Note
Output: the years are kept from overflowing int32 on the +1900, an open end is normalized to December 31 of the int32 maximum, and the direction marker is returned as it is, for the configuration class to normalize.
Returns
The decoded eras; empty if there is no era data.

◆ tm_stream_format()

template<typename TChar>
std::basic_string< TChar > IOv2::detail::tm_stream_format ( const timeio< TChar > & tio)

The format os << tm and is >> tm share: an expanded c, plus z and (Z) where those are needed.

The locale's c is first run through timeio::expand_format, because a z can sit inside a compound such as r or X where no search would find it; z and Z are then tested separately and whichever is missing is appended.

Each specifier is appended on its own. z restores tm_gmtoff, Z restores tm_zone, and neither stands in for the other: an abbreviation does not determine an offset (CST is US Central −6, China +8 and Cuba −5 at once), and an offset does not give a zone name. So en_US's c already carrying a Z still does not spare it the appended z. An appended Z is parenthesized and an appended z is not, giving ... +0800 (CST); a locale that already has a Z gets nothing appended for it and so stays ... Z z.

It is appended unconditionally, not based on this particular tm – sread holds a time_parse_context and no std::tm to inspect. Only one value-independent format, shared by both sides, keeps whatever can be written readable. Nothing is appended when the platform's std::tm has neither tm_gmtoff nor tm_zone, where appending would only put those characters in the output.
