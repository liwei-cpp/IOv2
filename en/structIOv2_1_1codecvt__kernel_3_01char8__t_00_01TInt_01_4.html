Detailed Description

template<typename TInt>
requires std::is_same_v<TInt, char32_t> || (std::is_same_v<TInt, wchar_t> && wchar_t_is_utf32)
struct IOv2::codecvt_kernel< char8_t, TInt >

Stateless UTF-8 encoding conversion kernel (char8_t <-> char32_t/wchar_t). Encodes and decodes code points directly according to the UTF-8 specification, requiring neither a locale nor any conversion state.

Note
Thread Safety: This class is NOT thread-safe. Concurrent access to the same instance from multiple threads requires external synchronization. Unlike codecvt_kernel<char, TInt>, concurrent construction of multiple instances is safe (no shared static state).
Code point validity is decided here, strictly per current UTF-8 (RFC 3629): surrogates in [0xD800, 0xDFFF] and anything above 0x10FFFF are rejected, in both directions. This differs from codecvt_kernel<char, TInt>, which leaves the decision to the locale's charset and where glibc lets code points above 0x10FFFF through. Use this kernel when strict USV semantics are wanted.

Conversion kernel between UTF-8 and 16-bit wchar_t (UTF-16), provided only where wchar_t_is_utf16 holds (Windows). The UTF-8 side shares its strict rules with codecvt_kernel<char8_t, char32_t> (detail::utf8_decode_one / detail::utf8_encode_one); this kernel only splits code points into UTF-16 units and joins them back.

A character outside the BMP takes two wchar_ts internally (a surrogate pair), which a call boundary can split, so the kernel holds half of one back:

  • writing: a run that ends in a high surrogate has it held, writing no bytes, and encoded with the low surrogate that opens the next run;
  • reading: a character outside the BMP decoded with one place left in the output has its high surrogate written and its low one held; the next in_helper hands that over first, consuming no bytes (has_pending_get() is true). While half a pair is held, is_init_state() is false, so switching direction and the like are refused; closing an output stream (unshift) with a high surrogate held throws, the input being incomplete.
Note
Thread safety: this class is NOT thread-safe. Concurrent access to one instance from several threads requires external synchronization.

Decode UTF-8 bytes into UTF-16 units. A low surrogate held from the previous call comes first, consuming no bytes; a character outside the BMP met with one place left in the output has its high surrogate written and its low one held. An incomplete character at the end and an invalid sequence are left unconsumed (from stops at its start).

Returns
false at an invalid UTF-8 sequence, true otherwise. How many units were written is how far to advanced.
Exceptions
cvt_errorIf a pointer range is inverted. A problem with the data is reported only through the return value.

Decode a UTF-8 byte sequence into internal characters (UTF-32 code points) and write them to the output buffer. Strictly validates UTF-8 format: rejects overlong encodings, surrogate code points, out-of-range values, and malformed continuation bytes.

Parameters

toPointer to the current write position in the output buffer (advanced as characters are written).
to_endOne-past-the-end pointer of the output buffer.
Returns
false at an invalid UTF-8 sequence, true otherwise. How many characters were written is how far to advanced.
Exceptions

Encode a run of UTF-16 units into UTF-8, as many as fit. Each character is started only with at least 4 bytes left. A surrogate pair is usually paired within the run; a run that ends in a high surrogate has it held (from moves past it, no bytes written).

Returns
false at a unit that cannot be encoded: a lone low surrogate, or a high surrogate not followed by a low one (from is left on the high surrogate; if that was held from the previous run, on this run's first unit, and the held one is dropped). true otherwise, including when encoding stopped for lack of room.
Exceptions
cvt_errorIf a pointer range is inverted. A problem with the data is reported only through the return value.

Encode a run of internal characters (UTF-32 code points) into UTF-8, as many as fit, and append them to the output buffer. Surrogate code points ([0xD800, 0xDFFF]) and values beyond the Unicode range (> 0x10FFFF) are rejected.

Each character is started only with at least 4 bytes left (the longest UTF-8 sequence); with less, encoding stops.

Parameters
fromPointer to the characters to encode, advanced past each one encoded.
from_endOne-past-the-end pointer of the characters to encode.
toPointer to the current write position in the output buffer, advanced as bytes are written.
to_endOne-past-the-end pointer of the output buffer.
Returns
false at an invalid code point: from is left on it and to after the characters before it. true otherwise, including when encoding stopped for lack of room (from short of from_end).
Exceptions
cvt_errorIf a pointer range is inverted. A problem with the data (an invalid code point) is reported only through the return value: only misuse by the caller throws.
Note
Precondition: from/from_end and to/to_end must each point into the same array; behavior is undefined otherwise. std::greater enforces a total order across pointers regardless of provenance, but the pointer subtractions below require same-object provenance per [expr.add]/5.
