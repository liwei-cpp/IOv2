Detailed Description

The part that does the work behind stdin_root_cvt: it holds the device, the read buffer and whether it is synchronized, and implements all the reading. It is a singleton (stdin_shared_imp), and stdin_root_cvt is only the handle that goes into a converter pipeline and passes calls on to it; so every standard input stream (cin, wcin) reads the same buffer and the same device, and they agree on the synchronization as well.

Neither copyable nor movable; sing_temp builds it and it is never destroyed. The streams using it serialize its operations with their object lock (the one cin and wcin share); synced() may also be called without it, for synced_with_stdio().

Reads up to to_max bytes. While the buffer holds bytes (read ahead unsynchronized, or rolled back or handed back and refused by the device) it hands out only those and does not go to the device, so the read may be short. Only with the buffer empty does it read the device: synchronized, nothing is read ahead, so it reads up to to_max bytes straight into to, bypassing the buffer; unsynchronized, it fills the whole buffer first and hands out from there.

◆ get_buf()

template<bool Saturate = false>
auto IOv2::detail::stdin_root_cvt_imp::get_buf ( std::size_t to_max)
inline

For cvt_reader: takes to_max bytes, refilling from the device when the buffer falls short – what is left moves to the front, and the refill fills the buffer unsynchronized and covers only the shortfall synchronized. The bytes stay in the buffer, for the caller to decode in place and roll back if need be. With Saturate false it returns (pointer, count), possibly fewer than to_max; with Saturate true it requires exactly to_max, returns the pointer, and throws if the end comes first.

Exceptions
cvt_errorto_max is 0 or exceeds s_buffer_length; with Saturate, the end comes first.

◆ rollback()

void IOv2::detail::stdin_root_cvt_imp::rollback ( std::size_t len)
inline

For cvt_reader: moves the read cursor back by len bytes, then hands everything left in the buffer back to the device through dunget() as a whole – handing back only the rolled-back bytes would let the bytes behind them be read first. If the device refuses (fd mode, or Windows), the bytes stay in the buffer and the next read hands them out first as before.

Exceptions
cvt_errorlen is 0 or exceeds the bytes handed out.

◆ unget()

template<std::bidirectional_iterator It>

void IOv2::detail::stdin_root_cvt_imp::unget ( It first,
It last )
inline

Takes the bytes [first, last) handed back from above, so that the next read gets them first.

With the buffer empty it tries dunget() first, and the bytes the device takes are C stdio's. If the device refuses (fd mode, or Windows), or the buffer still holds bytes (those come after the ones handed back, so giving the device only these would turn the order around), the bytes go into the buffer in front of what is left there; C stdio does not see them then, but every standard input stream reads them.

What comes back is usually what was just read, which goes back in front of the cursor with nothing moved. When there is no room in front, what is left moves to the end of the buffer, leaving all the free space in front so that later calls move nothing; when the buffer as a whole is too small it doubles, without a limit: the bytes already occupy memory above, so a limit would save nothing. A grown buffer returns to its usual size once drained.

Exceptions
std::bad_allocGrowing failed; the buffer, the device and the FILE are then unchanged.
