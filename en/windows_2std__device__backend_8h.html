Detailed Description

Windows backend of std_device: fd mode is built on the CRT's _read(), stdio mode goes through the FILE of stdin (_lock_file + fread).

Note
fd 0 stays in the CRT's default text mode (CRLF reads as LF); this backend does not call _setmode, which would change process-wide state that the user's own stdio relies on. The cost: in text mode _read takes a 0x1A byte (Ctrl+Z) as EOF, on pipes and redirected files as well as on a console, so binary data fed through stdin is cut off at its first 0x1A.
There is no O_NONBLOCK and no EINTR, so reads need no retry.
Stdio mode needs fd 0 in ANSI text mode or binary mode: once the user _setmodes it to _O_U16TEXT / _O_U8TEXT / _O_WTEXT, the CRT's narrow read functions no longer apply.
