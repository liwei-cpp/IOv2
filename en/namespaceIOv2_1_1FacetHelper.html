Insert grouping separators sep into the character sequence [first, last) according to grouping, write the result into the output buffer starting at out, and return a pointer one past the last element written.

Preconditions
  • grouping is non-empty. [asserted in debug builds]
  • [first, last) is a valid range, i.e. first <= last. Passing first > last converts last - first into an enormous unsigned width and writes far past the output buffer. [asserted in debug builds]
  • out points to an output buffer with sufficient capacity to hold (last - first) characters plus one separator (sep.size() characters) per non-leading group; callers are responsible for sizing the buffer. (last - first) * (1 + sep.size()) is always enough. [not validated]

◆ adjust_grouping()

void IOv2::FacetHelper::adjust_grouping ( std::vector< uint8_t > & grouping)
inline

Normalise a raw POSIX-style grouping vector in-place to the internal convention, or clear it if it carries no usable constraint.

Internal convention (uint8_t, platform-independent)
  • 1–255: explicit group size.
  • 0: stop — no further grouping after this point (the ONLY sentinel).
  • The LAST element (if in 1–255) is implicitly repeated for all remaining groups. If the last element is 0, the explicit stop wins.
Conversions applied to raw POSIX input
  • POSIX "0 = repeat previous": the 0 and everything after it is dropped. POSIX [N1, ..., Nk, 0, ...] becomes [N1, ..., Nk] in our convention, because last-element implicit repeat already covers that semantic exactly.
  • POSIX CHAR_MAX (= stop): rewritten to internal 0. CHAR_MAX is 127 on signed-char platforms and 255 on unsigned-char platforms; callers do not need to know the platform's char signedness after this step.
Note
Order matters: stripping POSIX "0 = repeat" MUST happen before the CHAR_MAX → 0 rewrite, otherwise the newly-introduced internal stop sentinel would be mistaken for a POSIX repeat-previous marker and dropped.
Parameters
groupingThe raw POSIX grouping vector to normalize in place.

◆ is_c_locale_name()

bool IOv2::FacetHelper::is_c_locale_name ( const std::string & name)
inline

Determine whether the locale name name designates the C/POSIX locale.

POSIX locale names have the form language[_territory][.codeset][@modifier]. Spellings such as "C.UTF-8", "C.utf8" and "C.UTF-8@euro" designate the same locale as "C", but an exact comparison cannot recognize them: the codeset segment is normalized before lookup (non-alphanumeric characters stripped, then lowercased), so the set of accepted spellings is not finite. This function compares the language segment — the part preceding . and @ — instead. That segment is itself case-sensitive (neither "c" nor "posix" is a valid name), so no case folding is applied.

Comparing the language segment alone is not enough: "C.BOGUS", "C@euro" and "POSIX.utf8" all have a C/POSIX language segment, yet newlocale() rejects them. A matching segment is therefore followed by a clocale_wrapper probe, which throws if the name cannot be instantiated. Validating here rather than leaving it to the caller's regular path avoids depending on the implicit premise that every such path constructs a clocale_wrapper of its own. "C" and "POSIX" are guaranteed to exist by the standard and short-circuit without a probe; names whose language segment does not match (say "en_US.BOGUS") are not this function's to claim and return false without being probed.

Parameters
nameThe locale name to test.
Returns
true if the language segment of name is "C" or "POSIX", false otherwise.
Exceptions
io_errorThe language segment is "C" or "POSIX" but newlocale() cannot instantiate the name.

◆ punct_distinct()

template<typename CharT>
bool IOv2::FacetHelper::punct_distinct ( std::basic_string_view< CharT > sep,
std::basic_string_view< CharT > point )
inline

Whether the thousands separator and the decimal point can be told apart in input: both are non-empty, and neither is a prefix of the other.

Parsing compares the input against both at once and settles on one at the first character where they differ. Were one a prefix of the other (equality included), the shorter would always match first and the longer could never be read, which leaves turning grouping off as the only option.

Returns
true if they can be told apart.

◆ take_punct()

template<typename TIter, std::sentinel_for< TIter > TSent, typename CharT>
punct_kind IOv2::FacetHelper::take_punct ( TIter & beg,
TSent end,
std::basic_string_view< CharT > sep,
std::basic_string_view< CharT > point,
bool consume_point )
inline

Recognises the thousands separator or the decimal point at the current input position; either may be several characters long.

The input is compared against both at once and settled at the first character where they differ; the caller makes sure the two can be told apart (see punct_distinct) and passes an empty string for one that does not take part. Characters read on trial that turn out to be no punctuation are put back with step_back, and the number ends there as usual: with U+202F (UTF-8 E2 80 AF) as the separator, 100€ (€ being E2 82 AC) reads as 100 and leaves the € in the input. Where the iterator cannot put them back the result is punct_kind::torn, and the characters read are lost.

Parameters
consume_pointWith false, a decimal point found is not read past (the part of a multi-character one already read is put back if possible): integer parsing stops in front of the point and leaves it in the input.

◆ verify_grouping()

bool IOv2::FacetHelper::verify_grouping ( const std::vector< uint8_t > & grouping,
const std::vector< uint8_t > & grouping_tmp )
inline

Verify whether the parsed grouping sequence grouping_tmp conforms to the numpunct::grouping constraint specified by grouping.

Preconditions
Both grouping and grouping_tmp must be non-empty; non-emptiness is validated only by assert() in debug builds; release builds rely on the caller. Violating the precondition in release causes size() - 1 to underflow to SIZE_MAX and subsequent indexing to read out of bounds. Callers guarantee non-emptiness because grouping_tmp is only populated inside !grouping.empty() branches, so the non-emptiness of grouping_tmp implies the non-emptiness of grouping.

grouping uses the internal uint8_t convention established by adjust_grouping(): 1–255 are explicit group sizes, 0 is the sole stop sentinel, and the last 1–255 element is implicitly repeated for all remaining groups.

Parameters
groupingThe reference grouping specification (from numpunct::grouping), using the internal uint8_t convention.
grouping_tmpThe grouping sizes actually observed during parsing.
Returns
true if grouping_tmp conforms to grouping; false otherwise.
