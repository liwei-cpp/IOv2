Detailed Description

template<bool IsIn, bool IsOut, typename CharType>
requires ((IsIn || IsOut) && (std::is_same_v<CharType, char> || std::is_same_v<CharType, char8_t>))
class IOv2::basic_file_device< IsIn, IsOut, CharType >

A file device template based on the C FILE*.

This class wraps the C standard I/O library, providing an RAII-style interface for managing files. It can be configured as read-only, write-only, or read-write via template parameters.

Note
Supports POSIX (Linux, macOS) and Windows; the platform-specific operations, such as opening and seeking, live in the backends under device/platform/.
Files open in binary on every platform: what is read and written are the file's bytes, positions and sizes count bytes, and on Windows too there is no translation between \r\n and \n. Newline translation, where wanted, belongs in the converter layer.
This class is not thread-safe; multi-threading is handled at a higher level.
Template Parameters
IsInSpecifies if the device supports input (reading).
IsOutSpecifies if the device supports output (writing).
CharTypeThe character type, currently supports char and char8_t.

default

Destructor: defaulted; the flush is done by m_file's deleter.

The FILE* is held in a std::unique_ptr<FILE, file_deleter>, and the deleter's std::fclose() flushes the stdio buffer before closing, so an output device needs no separate dflush() here. The price is that a failure goes unseen: fclose()'s return value is discarded, and a destructor could not report it anyway. To see a flush failure, call dflush() or close() explicitly before destruction – the latter does the dflush() first and throws device_error if either the flush or the close fails.

template<bool IsIn, bool IsOut, typename CharType>
void IOv2::basic_file_device< IsIn, IsOut, CharType >::close ( )
inline

Closes the file.

This function guarantees that the file handle is released regardless of whether an exception occurs. For output devices, it first attempts to flush the buffer (dflush). If an exception occurs during flushing, the file handle is still reset before the exception is re-thrown. fclose()'s result is checked too: a close can fail on its own after a successful flush (EIO from close(2), say), and then device_error is thrown; when both fail, the earlier flush failure is the one reported. Either way the file is closed on return or throw.

Exceptions
device_errorIf the flush or the close fails.

Reads data from the device.

If the FILE's error indicator is already set before the read (left by an earlier write, flush or seek that failed), it is cleared first, so that only this read's error is reported; otherwise nothing is cleared, and the EOF indicator stays set once the end of the file is reached. On a read error after part of the data was read, that part is returned, and the next call reads again and reports the error if it is still there.

Parameters
sPointer to the buffer where the read data will be stored.
nThe number of characters to read.
Returns
The number of characters actually read.
Exceptions
device_errorIf the file is not open, the buffer is null, or reading fails before any character is read.
