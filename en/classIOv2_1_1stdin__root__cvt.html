Detailed Description

The root converter of the standard input streams: built on the std_input_device on fd 0, with a read buffer, and whether it is synchronized is a runtime switch.

This class is only a handle and holds no state: the device, the buffer and the synchronization flag live in the one detail::stdin_shared_imp, which implements the reading as well, and every standard input stream (cin, wcin) works through it. So they read one buffer: unsynchronized, bytes one stream read ahead are there for the other to read on; there is one synchronization setting, so switching one switches them all; and bytes read ahead that reset() or a converter's automatic recovery drops (both install a device again) are dropped for every standard input stream. The object lock cin and wcin share serializes these operations.

Unsynchronized, it reads as much as the buffer can take whenever it has to go to the device, and the device reads fd 0 directly. Synchronized, it asks the device only for the bytes the caller is still short of and reads nothing ahead – a character-at-a-time read reads the device a byte at a time; the device switches to stdio mode along with it (std_device::stdio_mode()), reading through stdin's FILE and sharing its buffer with C stdio. Bytes already read ahead when it switches to synchronized are handed out first as usual, and only then is reading on demand, so a switch loses no input. The mode is switched through adjust(stdin_sync{...}); a device installed by attach() (reset() and a converter's automatic recovery install a default-constructed one) is set to the current mode.

When a converter above rolls back bytes it has not decoded through cvt_reader (wcin left with half a multibyte character at the end of the input, say), what is left in the buffer goes back to the device as a whole through std_device::dunget(), so that C stdio reads it next when synchronized; if the device refuses (fd mode, or Windows), the bytes stay in the buffer as before.

A stream handing back what it peeked at or had put back through unget() goes to dunget() first as well, and the bytes go into the buffer if the device refuses or the buffer still holds bytes; see stdin_root_cvt_imp::unget().

Input only: no writing, positioning or switching, and bos() always settles on input. It does not derive from root_cvt.
