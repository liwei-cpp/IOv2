template<bool IsIn, bool IsOut, typename CharType>
requires ((IsIn || IsOut) && (std::is_same_v<CharType, char> || std::is_same_v<CharType, char8_t>))
class IOv2::basic_file_device< IsIn, IsOut, CharType >

基于 C FILE* 的文件设备模板。

封装了 C 标准 I/O 库，提供了一个 RAII 风格的接口来管理文件。 它可以通过模板参数配置为只读、只写或读写模式。

注解
支持 POSIX（Linux、macOS）与 Windows；打开、定位等平台相关操作在 device/platform/ 下的后端里。
文件在所有平台上都以二进制打开：读写的就是文件里的字节，位置与大小都以字节计， Windows 上也不做 \r\n 与 \n 的转换。需要换行转换时，在转换器层处理。
此类不是线程安全的，多线程并发由更高层次的代码处理。
模板参数
IsIn指定设备是否支持输入（读取）。
IsOut指定设备是否支持输出（写入）。
CharType字符类型，当前支持 char 和 char8_t。

析构函数：默认实现，冲刷由 m_file 的删除器完成。

FILE* 由 std::unique_ptr<FILE, file_deleter> 持有，删除器调用的 std::fclose() 在关闭前会冲刷 stdio 缓冲，因此输出设备无需在此另行 dflush()。代价是失败无从得知： fclose() 的返回值被丢弃，析构函数也无法报告。要拿到冲刷失败，请在销毁前显式调用 dflush() 或 close()——后者先 dflush() 再关闭，冲刷或关闭失败都会以 device_error 抛出。

template<bool IsIn, bool IsOut, typename CharType>
void IOv2::basic_file_device< IsIn, IsOut, CharType >::close ( )
inline

关闭文件。

该函数保证无论是否发生异常，文件句柄都会被释放。 对于输出设备，会首先尝试刷新缓冲区（dflush）。如果刷新过程中抛出异常， 会先确保文件句柄被正确关闭，然后再重新抛出捕获到的异常。fclose() 的返回值也会 检查：冲刷成功之后关闭本身仍可能失败（如 close(2) 报 EIO），此时抛出 device_error； 两者都失败时报告先发生的冲刷失败。无论哪种情况，返回或抛出时文件都已关闭。

异常
device_error冲刷或关闭失败。

从设备读取数据。

读之前若 FILE 的错误标志已置上（之前的写、冲刷或定位失败留下的），先清掉，使本次 只报本次读的错误；平常不清，读到文件尾的 EOF 标志照旧粘住。读出错时若已读到一部分， 先返回这一部分，下一次调用重新读，错误仍在就在那时报出。

参数

n要读取的字符数。
返回
实际读取的字符数。
异常
device_error如果文件未打开、缓冲区为空，或读取出错且一个字符也没读到。
