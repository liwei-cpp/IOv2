◆ ctype_byte_is_char()

bool IOv2::detail::ctype_byte_is_char ( int ,
clocale_handle  )
constexprnoexcept

字节 c 在 loc 中是否为一个独立的字符，可交给 is*_l/to*_l。

glibc 上恒为 true：多字节 locale 中它自己就不对高字节分类。macOS 则把字节当作同值的 Unicode 码位来分类，不看编码：UTF-8 locale 下 0x80–0x9F 成了 cntrl、0xE9 成了字母，而 它们在 UTF-8 中只是多字节序列的一部分。故 macOS 上多字节 locale 的高字节一律不属于 任何类别、大小写不变，与 glibc 相同。

inlinenoexcept

direction 被规范化为恰好 +1 / -1，使得以下线性公式对所有纪元类型均一致有效：

era_year = offset + (calendar_year - from_year) * direction
IOv2::tz_level::offset
@ offset
解析 z 的 UTC 偏移；Z 仍按字面量处理。
定义 timeio.h:742

规范化逻辑参照 glibc 的 era.c（约第 98 行， https://github.com/lattera/glibc/blob/master/time/era.c）： 前向纪元（from ≤ to，如公元 AD、日本皇纪、泰国佛历）方向标记直接映射， '+' → +1，'-' → -1；后向纪元（from > to）方向标记取反：from_year 是纪元起点，to_year 是"负无穷"的哨兵，公历年份离起点越往过去，(calendar - from_year) 越负，取反后的方向把这段 距离变成正的纪元年份，同一个公式于是对两个时间方向都成立。

template<typename CharT>
std::optional< std::basic_string< CharT > > IOv2::detail::timeio_normalize_format ( std::basic_string_view< CharT > fmt)

把 locale 提供的时间格式串归一化为本库 timeio 能识别的形式。

C 库给出的格式串（POSIX 上来自 nl_langinfo()）是 locale 数据，不是用户写的；其中可能出现 glibc 的 扩展语法，而本库的 timeio 只实现 '' [E|O]? <说明符> 这一标准文法。若原样保留， timeio 的 put 侧会把不认识的序列连同 % 一起字面回显（与 strftime 对真正未知 说明符的行为一致），使用户仅写了 c / x 却得到含 % 的输出，并可能被 get 侧 静默读回错值。本函数在 locale 数据进入本库时做一次转换：

  • 丢弃补位标志（- _ 0 ^ #）与字段宽度：它们只影响填充与大小写， 丢弃后字段顺序、分隔符、语言全部保留；
  • 把有等价标准说明符的 glibc 扩展改写过去：l → I、k → H、P → p；

注解
本函数只作用于 locale 提供的格式串；用户自己传给 put_time / get_time 的格式串不经过这里，其未知说明符仍按原契约回显。
模板参数
CharT格式串的字符类型；窄、宽配置类共用。
参数
fmtlocale 提供的格式串。
返回
归一化后的格式串；若含无等价物的说明符，则为 std::nullopt， 由调用方代入整串兜底值。
