详细描述

template<typename TChar>
struct IOv2::ostream_operators< TChar >

为输出流提供各类插入操作的混入（mix-in）基类。

本模板集中承载 put、write 等成员，供具体输出流类型派生使用；这些成员通过 deducing-this（this TSelf& self）以派生类的具体类型执行操作。每个操作先取本流的 io_mutex()，再在锁内构造输出哨兵以完成前置准备，并将异常统一交由流的 handle_exception 处理，从而按异常掩码更新流状态。

模板参数
TChar字符类型。

◆ flush()

template<typename TChar>
template<typename TSelf>
void IOv2::ostream_operators< TChar >::flush ( this TSelf & self)
inline

刷新本流：把缓冲区写出到底层设备。

刷新不经哨兵，而是直接以 std::lock_guard 持有本流的 io_mutex()（该锁为递归锁） 直至刷新结束。由此：

  • **并发刷新被串行化**：多个线程同时 flush() 同一流时逐个进入，每个都真正完成一次 刷新（不是"先到者刷、其余跳过"的弱语义）；底层缓冲区不会被并发操作。
  • **写与刷互斥**：put/write/operator<< 在其哨兵生命周期内持有同一把 io_mutex()，故写与刷不会并发。

本函数**不刷新本流的 tie 目标**，只作用于本流。tie 刷新只由 I/O 操作的哨兵在其入口经 tie_target::try_flush() 触发，并在那里沿 tie 链逐级传递；本函数不调用 try_flush()， 也就不会递归回到本流，无需任何"正在刷新"自旋/跳过标志。

输出前的读写模式切换由 iochannel::flush() 自行完成（其内部会 switch_to_put()）， 故此处无需哨兵代劳。

警告
本函数在失败态下拒绝写出，但生命周期收尾的冲刷不受状态位约束。 流的 operator bool 为假时（任一失败位；单独的 eofbit 不算），本函数在触碰 缓冲区之前就抛 stream_error，经 handle_exception 转成 strfailbit， 那批待刷字节一个也没写出去。但流的**析构**、detach() 与**赋值**都不看状态位： 它们的冲刷发生在下一层（~root_cvt / root_cvt::detach() / root_cvt::operator=），而 root_cvt 拿不到 ios_state，于是同一批字节照样 dput 给设备。因此「flush() 被拒」**不意味着**这批字节不会到达设备； 真要丢弃，只能 detach() 之后弃用取回的设备，或者先 clear() 再 flush()。
注解
上一条与标准库同构，不是本库的特例：std::ofstream 在失败态下 flush() 同样 什么都不写，而 ~basic_ofstream() 照样冲刷 put 区，分层的原因相同。本库没有 close()，最接近的 detach() 会把清理阶段的首个异常以 exception_ptr 交还调用方。
模板参数
TSelf派生的具体流类型（由 deducing-this 推导）。

向流写入单个字符。

模板参数
TSelf派生的具体流类型（由 deducing-this 推导）。
参数
c要写入的字符。
force_flush为 true 时，无论 unitbuf 标志是否置位，本次写入结束后都刷新 缓冲区并对设备 dflush()；为 false（默认）时只遵循 unitbuf。
返回
流自身的引用。
注解
本参数存在的原因：「这一次要不要刷新」从来都是一个**局部**信息。若没有它，像 endl 这样需要强制刷新的操纵符只能绕道去临时置位再复位全局的 unitbuf 标志，而那个 读-改-写既非原子也非异常安全。
