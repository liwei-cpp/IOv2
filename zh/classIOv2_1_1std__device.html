详细描述

template<int ID>
requires ((ID == detail::std_in_fd) || (ID == detail::std_out_fd) || (ID == detail::std_err_fd))
class IOv2::std_device< ID >

封装标准 I/O 文件描述符的设备。

这个类模板通过标准流的文件描述符（0、1、2） 来创建一个 I/O 设备。它为标准输入提供了阻塞读取（fd 设了 O_NONBLOCK 时以 poll 等待， EINTR 自动重试）和 EOF 处理，并为标准输出/错误提供了写入和刷新功能。

注解
支持 POSIX（Linux、macOS）与 Windows；平台相关的读操作在 device/platform/ 下的后端里。 下文的 O_NONBLOCK、poll、EINTR 只适用于 POSIX，Windows 的差异见 Windows 后端。
此类不是线程安全的，多线程并发由更高层次的代码处理。
输出侧经 fwrite 写，**不处理 EAGAIN**：fd 设了 O_NONBLOCK（终端上它同时作用于 fd 0/1/2）时，写满内核缓冲的那部分返回失败、字节丢失，流置 devfailbit。std::cout 同样如此（实测）。
终端处于 raw 模式且 VMIN == 0 时，阻塞 fd 上 read 超时返回 0，被当成（粘性的）EOF； 设了 O_NONBLOCK 的 fd 则以 poll(-1) 等待，不受 VTIME 影响。两者行为不同。
macOS 的 poll 不支持终端以外的字符设备（如 /dev/zero），报 POLLNVAL：stdin 重定向自 这类设备时，探测后的 dget 只返回缓存的那 1 个字节；fd 还设了 O_NONBLOCK 时，read 遇 EAGAIN 后的等待抛 device_error。终端与管道不受影响（实测）。

stdin 有两种读法，由 stdio_mode() 切换：缺省的 **fd 模式**直接 read() fd 0，绕过 stdio 缓冲；**stdio 模式**在 stdin 的 FILE 锁内用 fread 读，与 C stdio 共用一份缓冲。标准输入 流对象经 sync_with_stdio() 切换它：同步时用 stdio 模式。

警告
fd 模式下请勿在 stdin 上将 std_input_device 与 C stdio 函数（scanf, fgets, getchar 等）混合使用：stdio 预读进 FILE 缓冲的字节本设备看不到，反之亦然。
模板参数
ID文件描述符。必须是 0、1 或 2（POSIX 上即 STDIN_FILENO、STDOUT_FILENO、 STDERR_FILENO）；请用别名 std_input_device、std_output_device、std_error_device。

◆ deof()

template<int ID>
bool IOv2::std_device< ID >::deof ( )
inlinenodiscard

检查标准输入流是否已到达文件末尾（EOF）。

采用**探测式**判断：若尚未确定 EOF、且内部没有已缓存的预读字节，会尝试从设备 读取 1 个字节来确定末尾状态：

  • 读到字节：说明尚未到 EOF；该字节被缓存在内部，并由**下一次 dget() 首先返回** （连同此刻已就绪的数据，但不为凑数等待），不会丢失、不会打乱顺序；本函数返回 false。
  • 读到 0（EOF：文件读完、管道写端全部关闭、终端上一行开头的 ^D）：置位 EOF 标志并 返回 true。

终端**挂断**（pty 主端关闭）在 Linux 上不算 EOF：read 得 EIO、poll 报 POLLERR，按设备错误 抛 device_error，流上是 devfailbit（std::cin 此时报 eof|fail）；阻塞 fd 上偶尔也会 先读到 0 而得 EOF，取决于内核时序（实测）。macOS 上挂断即 EOF：poll 报 POLLIN|POLLHUP， read 返回 0（实测）。

警告
本函数**可能阻塞**：当流上暂时无数据、也尚未到达 EOF 时，它会一直等待， 直到有字节到达或确认 EOF 为止。因此在交互式终端上调用会等待用户输入。
注解
EOF 是**粘性**的：一旦探测到 EOF，后续调用立即返回 true（不再读取）。
上面描述的是 fd 模式。stdio 模式下（见 stdio_mode()）在 FILE 锁内读 1 个字节再 ungetc 退回，字节留在 FILE 里，C stdio 函数接着也能读到；EOF 即 feof(stdin)， clearerr(stdin) 可以清除。
返回
如果已到达 EOF，则为 true。
异常
device_error如果底层读取或轮询发生错误。

template<int ID>
std::size_t IOv2::std_device< ID >::dget ( char * s,
std::size_t n )
inline

从标准输入读取数据。

这是一个阻塞式读取操作，使用 poll 来等待数据可用，并能正确处理 EINTR 中断。 若此前 deof() 探测时预读并缓存了 1 个字节，本函数会**首先返回该缓存字节**，并把 设备上**此刻已就绪**的数据一并读出（零超时 poll 判定），从而保证字节顺序不被打乱、 探针之后的整块读取仍是整块；但**不会**为了凑够 n 个字节而在设备暂时无数据时等待 ——那种情形下只返回这一个字节（短读），它正是调用方要的东西。

参数
s存储数据的缓冲区。
n要读取的字节数。
返回
实际读取的字节数，可能少于 n。如果到达 EOF，则返回 0。
异常
device_error如果发生读取或轮询错误。
注解
遇到 EOF 时立即返回 0，符合 POSIX read() 语义。 EOF 是粘性的，后续调用也会继续返回 0。
上面描述的是 fd 模式。stdio 模式下（见 stdio_mode()）在 FILE 锁内 fread， 读满 n 个字节或遇到 EOF 才返回（缓存的预读字节仍先交出、单独返回）；EOF 即 feof(stdin)，clearerr(stdin) 之后可以接着读。

把 s[0..n) 退回给 C stdio，使下一次读取（本设备的 dget()，或 getchar() 等） 先按原顺序得到这些字节。

要么全部退回、返回 true，要么一个也不退、返回 false，调用方据此决定字节是否仍由自己 保管。只有 stdio 模式（见 stdio_mode()）可能成功：fd 模式没有与 C stdio 共用的缓冲， 退回没有意义；切换前 fd 模式探到的字节尚未交出时也拒绝，因为退回的字节与它谁先谁后 说不清。stdio 模式下退回经 ungetc，在 stdin 的 FILE 锁内从最后一个字节起逐个进行： POSIX 上标准只保证 1 个字节，多出的部分 glibc 与 BSD 只在内存不足时失败，其它 libc 可能更早失败，半途失败时已退回的字节被重新读走；Windows 上总是返回 false——UCRT 没有独立的回退区，空间不够时 ungetc 可能改写尚未读的字节而照样报告成功，FILE 又不透明、无从事先查询。

注解
ungetc 会清除 FILE 的 EOF 标志，而标准没有重新置位它的接口：退回失败时字节都 已撤回，但 EOF 标志可能已被清除。
参数
s要退回的字节。
n字节数；为 0 时什么也不做，返回 true。
返回
全部退回为 true；没有退回为 false。
异常
device_errors 为空而 n 不为 0。

◆ stdio_mode() [2/2]

template<int ID>
void IOv2::std_device< ID >::stdio_mode ( bool on)
inlinenoexcept

切换 stdin 的读法：true 为 stdio 模式（经 stdin 的 FILE），false 为 fd 模式 （直接 read() fd 0，缺省）。

stdio 模式下 dget 像 fread 一样要读满 n 个字节或遇到 EOF 才返回，所以调用方只应向它要 确实需要的字节数（stdin_root_cvt 同步时正是如此）；EOF 以 FILE 自己的粘性标志为准， clearerr(stdin) 之后可以接着读。

切换本身不做 I/O。已缓存的预读字节（fd 模式下 deof() 探到的）不论哪种模式都由下一次 dget() 先交出；fd 模式记下的 EOF 在切到 stdio 模式时清除。切回 fd 模式时，FILE 缓冲里 尚未读走的字节（包括 stdio 模式下 deof() 经 ungetc 退回的那个）本设备不再看得到—— 没有可移植的办法把它们取出来。
