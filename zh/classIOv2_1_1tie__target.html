详细描述

承载多态 try_flush() 接口的抽象基类。

提供纯虚的 try_flush()，使得可通过基类指针以类型无关的方式刷新任意 tie 目标；输出流的 实现由 CRTP 派生类 out_tie_target<T> 给出。

警告
用户不得派生本类。 本类只供 out_tie_target<T> 实现（构造函数为 protected 只为此），tie 目标应当是本库的一条输出流；派生本类不对应任何合理的用法。它的两个 虚函数还各有调用方看不见的约束：try_flush() 在发起方持有自己的流锁时被调用， tied_to() 在持有进程级 tie_graph_mutex() 时被调用。自定义实现若在其中阻塞地 取锁或调用 tie()，就会死锁，或对非递归锁重复加锁（未定义行为）。

virtual tie_target * IOv2::tie_target::tied_to ( ) const
inlinenodiscardvirtualnoexcept

本节点在 tie 图上的出边：本流 tie 到的目标；不带出边的节点返回 nullptr。

供 basic_stream_common_operators::check_tie 判环、out_tie_target::try_flush() 逐级刷新 时沿链遍历。经虚函数而不是交叉转换取出边：普通流与标准流的公共基类是 basic_stream_common_operators 的两个不同实例化，dynamic_cast 到其中一个，链会在另一种 流处断开，经过它的环就查不出来，刷新也传不过去。check_tie 在持有进程级 tie_graph_mutex() 时调用它，try_flush() 则不持该锁；out_tie_target 的实现只做原子读， 故为 noexcept。 缺省返回 nullptr，即不带出边的节点。

被 IOv2::out_tie_target< T >, IOv2::out_tie_target< iostream< TDevice, TChar > >, IOv2::out_tie_target< ostream< TDevice, TChar > > , 以及 IOv2::out_tie_target< stdout_api< TDevice, TChar > > 重载.

◆ try_flush()

virtual void IOv2::tie_target::try_flush ( )
pure virtualnoexcept

尽力刷新本流及其下游 tie 链的纯虚接口；由 out_tie_target<T> 实现。

警告
实现必须非阻塞。 哨兵在持有自己流的锁时调用本函数，而这条加锁边对用户不可见， 他无从把它纳入自己的锁序；实现若改用阻塞的 lock()，AB-BA 死锁立即回归。取锁 失败时必须直接返回，不得等待，也不留任何补偿——tie 因此是尽力而为，不是保证。 这只管流锁：取到锁之后，标准流的刷新（fflush）仍可能等 stdio 的 FILE 锁，那条 加锁边按「先流锁、后 FILE 锁」处理，见 IOv2::sync 的第二条 @warning。
实现必须自行吞掉刷新过程中的一切异常，故声明为 noexcept。 本函数的调用点 位于哨兵构造函数中，而哨兵构造在**发起方**流的 try 块内（见 ostream_operators.h 的插入运算符）；异常一旦逸出，就会被那里的 catch 交给 发起方**的 handle_exception，于是本流（tie 目标）的失败被记成发起方的失败： 发起方会拿到一个描述**别人的 iochannel 的 cvt_error，并按异常类型置上自己 从未发生过的 cvtfailbit。noexcept 把"失败只记在 tie 目标身上"这条归属规则 变成编译期约束，而不再依赖每个调用点自觉包一层 catch (...)。

在 IOv2::out_tie_target< T >, IOv2::out_tie_target< iostream< TDevice, TChar > >, IOv2::out_tie_target< ostream< TDevice, TChar > > , 以及 IOv2::out_tie_target< stdout_api< TDevice, TChar > > 内被实现.
