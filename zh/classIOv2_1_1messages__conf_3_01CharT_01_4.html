template<typename CharT>
requires std::is_same_v<CharT, char32_t> || (std::is_same_v<CharT, wchar_t> && (wchar_t_is_utf32 || wchar_t_is_utf16))
class IOv2::messages_conf< CharT >

messages_conf 的 char32_t 与 Unicode wchar_t 特化。

messages_conf 中编码取决于 locale 的特化：char，以及 macOS 的 wchar_t。

从 .mo 文件加载 UTF-8 翻译字典，再将所有字符串转换为 CharT 类型：char32_t 与 UTF-32 的 wchar_t（Linux）逐码点，UTF-16 的 wchar_t（Windows）中 BMP 以外的字符成为 代理对。编码与 locale 无关，故构造时不带 locale 名。macOS 的 wchar_t 不是 Unicode， 由带 locale 名的特化处理（见 detail::messages_locale_encoded）。

模板参数
CharT字符类型：char32_t，或 UTF-32 / UTF-16 的 wchar_t。

从 .mo 文件加载 UTF-8 翻译字典，再按构造时给出的 locale 名 cvt_ft 的编码转换：

  • 该 locale 为 UTF-8：char 直接使用 .mo 的字节，不做校验，与 messages_conf<char8_t> 相同；macOS 的 wchar_t 交给该 locale 的 C 库解码。
  • 不是 UTF-8：char 先转成 Unicode 的 wchar_t，再转成该 locale 的编码（Linux、Windows）。 macOS 的 wchar_t 不是 Unicode，没有可靠的转换，char 与 wchar_t 都抛 io_error。

wchar_t 只在 macOS 上带 cvt_ft 参数。跨平台代码经 locale::involve_msg 并使用缺省 参数时，三个平台写法相同；像 involve_msg("app", "zh_CN", true) 这样按位置给出 throw_if_fail 的写法，用于 wchar_t 时在 macOS 上编译报错（第三个参数是 locale 名）。

模板参数
CharTchar，或 macOS 上的 wchar_t（见 detail::messages_locale_encoded）。

构造函数，加载指定域和语言的翻译字典。

参数
domain文本域名称。
lang候选语言字符串，或空字符串（按环境变量与系统语言偏好决定，见 filter_lang）。
throw_if_fail如果为 true（默认），加载失败时抛出异常； 否则静默地使翻译字典为空。只接受 bool：字符串字面量 不会被转成 bool，而是作为目录名选中带 dirname 的重载。
异常
io_error如果 throw_if_fail 为 true 且字典加载失败。

构造函数，加载翻译字典并进行编码转换。

与其他特化相比，此特化需要额外的 cvt_ft 参数：决定字符串编码的 locale 名。 这是公开、稳定的构造 API，因此不能将参数打包到结构体中，否则会破坏调用者， 或与兄弟特化的 (domain, lang) 参数形式产生不一致。

参数
domain文本域名称。
lang候选语言字符串，或空字符串（按环境变量与系统语言偏好决定，见 filter_lang）。
cvt_ft决定字符串编码的 locale 名（如 zh_CN.UTF-8）。
throw_if_fail如果为 true（默认），加载失败时抛出异常； 否则静默地使翻译字典为空。只接受 bool：字符串字面量 不会被转成 bool，而是作为目录名选中带 dirname 的重载。
异常
io_error如果 throw_if_fail 为 true 且字典加载失败。
