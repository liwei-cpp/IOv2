详细描述

stdin_root_cvt 背后真正干活的部分：持有设备、读缓冲与是否同步，并实现全部读取逻辑。 它是单例（stdin_shared_imp），stdin_root_cvt 只是放进转换器管线里的句柄，把调用转给它； 于是所有标准输入流（cin、wcin）读同一块缓冲、同一个设备，同步与否也随之一致。

不可拷贝、不可移动，由 sing_temp 构造、永不析构。操作由使用它的流的对象锁（cin、wcin 共用的那一把）串行化；synced() 另可不加锁调用，供 synced_with_stdio() 查询。

供 cvt_reader 用：取 to_max 个字节，缓冲里不够时向设备补——剩下的字节先移到开头， 不同步时补满缓冲，同步时只补还缺的。字节留在缓冲里，供调用方原地解码、必要时回退。 Saturate 为 false 时返回（指针，实际数量），可能少于 to_max；为 true 时要求恰好 to_max 个，返回指针，读满之前到达末尾则抛出。

异常
cvt_errorto_max 为 0 或超过 s_buffer_length；Saturate 时读满前到达末尾。

供 cvt_reader 用：把读取游标后退 len 个字节，再把缓冲里剩下的全部字节经 dunget() 整体还给设备——只还回退的那几个，排在它们后面的字节就会先被读到。设备拒绝时（fd 模式， 或 Windows）字节留在缓冲里，下一次读取照旧先交出它们。

异常

◆ unget()

template<std::bidirectional_iterator It>
requires std::same_as<std::iter_value_t<It>, char>
void IOv2::detail::stdin_root_cvt_imp::unget ( It first,
It last )
inline

接手上层退回的字节 [first, last)，使它们成为下一次读取最先得到的字节。

缓冲为空时先试 dunget()，设备收下就交给了 C stdio。设备拒绝时（fd 模式，或 Windows）， 或缓冲里还有字节时（它们在流中排在退回的字节之后，只还退回的字节会颠倒顺序），字节进 缓冲，放在剩余字节的前面；此时 C stdio 看不到它们，但所有标准输入流都读得到。

退回的通常是刚读走的字节，写回游标之前的位置即可，不移动任何数据。前面放不下时，剩余 字节移到缓冲末尾，把空闲空间都留在前面，之后的退回不再移动；总空间也不够就成倍扩容， 没有上限：这些字节本来就占着上层的内存，设上限也省不下什么。扩大的缓冲读空后恢复原来 的大小。

异常
std::bad_alloc扩容失败；此时缓冲、设备与 FILE 都没有改变。
