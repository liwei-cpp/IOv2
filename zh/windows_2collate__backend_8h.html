详细描述

collate facet 的 Windows 后端：直接调用 CompareStringEx 与 LCMapStringEx(LCMAP_SORTKEY)， 以 locale 的 LC_COLLATE BCP-47 名字定排序规则。

不用 UCRT 的 _strcoll_l/_strxfrm_l：前者给 CompareStringEx 加了 SORT_STRINGSORT， 后者调 LCMapStringEx 时却不加，于是排序键的顺序与比较结果不一致（真机实测 de-DE 下 "co-op" 比 "coat" 小，其排序键却比 "coat" 的大）。MSVC STL 的 collate 自己调 NLS， 也是同样的不一致。本后端两边都不加标志：标点在第一层被忽略，在上例上与 glibc 一致。

窄字符串先按 LC_COLLATE 的代码页用 MultiByteToWideChar 转成 UTF-16，带 MB_ERR_INVALID_CHARS：该代码页下的非法字节序列算失败，与 UCRT 的 _strcoll_l 相同。 LCMapStringEx 给出的排序键是字节串：窄字符的键就是这些字节，宽字符的键每个 wchar_t 放一个字节，与 UCRT 的 wcsxfrm 相同。

"C" locale 没有 BCP-47 名字，与 UCRT 一样按代码单元比较，排序键就是输入本身。宽字符 是 UTF-16 代码单元，故 "C" 下 BMP 以外的字符排在 U+E000–U+FFFF 之前。
